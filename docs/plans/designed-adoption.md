# Evaluate Designed in observable-web

**Decision accepted as [ADR-049](../../spec/adr/ADR-049-designed-component-library-adoption.md).** This file remains the live compatibility-findings record each new control family is evaluated against; the ADR records the accepted pattern.

Adopt shared controls incrementally if a consumer pilot passes. Observable's React 19 client, Vite CSS Modules support and npm workspace can consume Designed's compiled ESM. Designed's pnpm workspace is a producer detail. Routing, query state and telemetry rendering can keep their existing owners under [ADR-036](../../spec/adr/ADR-036-frontend-module-boundaries.md) and [ADR-016](../../spec/adr/ADR-016-grafana-visualization-strategy.md).

## Compatibility findings

| Observable surface | Designed fit | Decision |
| --- | --- | --- |
| [Button and Input](../../apps/frontend/src/components/ui/) | Native button and input semantics. Observable calls the destructive button variant `destructive`, Designed calls it `danger`. | Pilot through the existing exports. Preserve refs, default button type, form events, disabled behavior and consumer class overrides. |
| Badge, HealthDot and severity indicators | Designed Badge supports presentation. Observable Badge also supplies `role="status"` and HealthDot exposes a named state. | Keep severity mapping, labels and announcement behavior in Observable. No swap: Badge already renders through the Designed-token bridge (`styles.css`), so there is nothing left to integrate. |
| Empty state | Designed's `EmptyState` only accepts `icon`/`title`/`description`/`action` — no generic children slot and no per-slot `className`. Observable's `metadata` chip list and `compact` title-size override can't be expressed through it without reintroducing custom CSS the adoption is meant to remove. | Keep Observable's implementation. It already renders through the Designed-token bridge; no further integration possible without losing `metadata`/`compact`. |
| Select, confirm dialog, command palette | Observable Select exposes an actual `HTMLSelectElement`, option children and native change events. Designed Select is a compound control. Dialog and palette also own focus and portal behavior. | Keep native Select. Evaluate overlays individually after the pilot with keyboard, focus restoration and accessible-name tests. |
| Confirm dialog (overlay evaluation) | Designed's `AlertDialog` wraps Base UI: real focus trap, portal, and an `initialFocus`/`finalFocus` ref API, forwarded (though undeclared in its own prop types) through to the underlying Popup. Base UI disables pointer-outside dismissal for alertdialogs by design; Escape still fires `onOpenChange`, gated here by the existing `isPending` check since the component stays fully controlled by the `open` prop. `AlertDialogContent` (unlike `EmptyState`) accepts arbitrary children, so the consequences/elevated-context paragraphs needed no new slot. | Swapped. Preserves `role="alertdialog"`, accessible name/description wiring, Cancel-first focus (verified async via Base UI's post-paint floating-focus-manager, not the old synchronous effect), and explicit-confirmation requirement — existing `confirm-dialog.test.tsx` and the two consuming a11y tests (`obs_24_10`, `obs_25_10`) pass unchanged bar one `await waitFor` for the now-async initial focus. Fixed a pre-existing e2e failure (`experience-shell-s4`'s 320px-viewport confirm-resolve flow) as a side effect. Cost: Base UI's focus manager adds ~15.7 kB gzip to the main bundle — a real, overlay-specific price, unlike Button/Input. |
| Command palette (overlay evaluation) | Designed's `CommandPalette` owns `query` state internally with no `onQueryChange`/query-interception hook — `items` must be a static, homogeneous `{id, label, group, keywords, shortcut, disabled}` list filtered by its own internal `matchesQuery`. Observable's palette (`command-palette.tsx`) runs live async search across traces/services/incidents as the user types, with per-result-type (`nav`/`trace`/`service`/`incident`) custom rendering and navigation. There is no slot or callback to intercept the query string and substitute async, heterogeneously-rendered results. | Not swapped — hard mismatch, not a contract nuance to work around. Keep Observable's implementation. |
| Re-evaluation of upstream release (`designed-react@0.7.0`, `designed-icons@0.4.0`, `designed-tokens@0.6.0` unchanged) | Installed from the GitHub Packages registry (`npm install`), not git ref or tarball. `npm ls` confirms a single `@base-ui/react@1.9.0` and a single React 19 instance; no duplicate installs. All four upstream feedback items (#10-#13) verified against the installed package's `.d.ts`, not just source review. | All four resolved and verified. One new regression found and worked around: `Input`'s `size` prop narrowed from native `number` to `InputSize` union, breaking Observable's `Input` wrapper typecheck — not previously evaluated since it wasn't part of the original feedback batch (feedback #9). |
| Empty state (re-check) | `EmptyState` now accepts `children` (rendered after `action`), `classNames: {icon,title,description,action}` and `titleAs`, confirmed in the installed `0.7.0` types. | Unblocked. Not yet swapped — scheduling the swap (metadata as children, compact via `classNames.title`) is separate follow-up work, not part of this dependency bump. |
| Command palette (re-check) | `CommandPalette` now has controlled `query`/`onQueryChange`, `filter={null}` to disable internal filtering, `renderItem`, generic `Item extends CommandPaletteItem` and `enableGlobalShortcut`, confirmed in the installed `0.7.0` types. | Swapped. Observable keeps live async fetch, per-type matching (`getResults`) and navigation (`activate`); Designed now owns the dialog (Base UI `Dialog.Root`/`Popup`, real portal and focus trap), query input, keyboard nav (arrows/Home/End/Enter) and Escape-to-close (via Base UI's `useDismiss`, replacing the old manual `document` listener). `renderItem` renders the same per-type label text as before. Accessible name moved from `aria-label` to `aria-labelledby` (Designed's visually-hidden `Dialog.Title`) — updated `command-palette.test.tsx` to assert via `getByRole("dialog", { name: ... })` instead of the attribute. Found and fixed a double-`onClose` call: Designed's `onSelect` already triggers `onOpenChange(false)`, so `activate()` no longer calls `onClose()` itself. All 11 `command-palette.test.tsx` cases, the full `vitest` suite (1017/1017), and the full Playwright suite pass (one pre-existing, unrelated failure on `main` in `experience-shell-s1.spec.ts`, verified via `git stash`). Remaining gap: no loading/error-row slot during the async fetch window (feedback #8) — unchanged behavior from before the swap, since Observable's fetch was already silent until resolved. |
| Confirm dialog (re-check) | `initialFocus`/`finalFocus` are now declared on `AlertDialog.Content` and `Dialog.Content`, confirmed in the installed `0.7.0` types. | Done: removed the untyped `AlertDialogContentWithFocusProps` spread in `confirm-dialog.tsx`, now passes `initialFocus={cancelRef}` directly. `tsc --noEmit` and `confirm-dialog.test.tsx` pass. |
| Input (regression from this bump) | `InputProps` in `0.7.0` narrows `size` to `InputSize = "small" \| "medium" \| "large"`, which conflicts with Observable's `Input` wrapper re-exporting native `InputHTMLAttributes<HTMLInputElement>` (native `size: number`) and spreading props through. | Fixed: Observable's `InputProps` now `Omit<InputHTMLAttributes<HTMLInputElement>, "size">`. No caller passed native `size`. Filed as feedback #9 (undocumented breaking type change in a minor bump). |
| Copy button | Designed `CopyButton` has `value`, `copiedLabel`, `copiedDuration`, `onCopy`, `onError`. No error visual state and no size scale. Observable's `useCopyToClipboard` hook is also used outside the button, and `xs`/`sm` icon sizes are used in dense rows. | Not swapped. Keep the hook. Gaps: feedback #5. |
| Toolbar | `ToolbarRoot` wraps `@base-ui/react/toolbar` directly (role, orientation, `loopFocus`, disabled propagation), forwards `className` and `...rest`. Observable's `Toolbar` was a plain `<div role="toolbar">` with no Base UI underneath — real roving-tabindex/keyboard-nav behavior was missing. Designed's `.root` layered styles (background/border/padding) would otherwise show through since Observable's `modern-toolbar` class only sets `display`/`gap`/`wrap`, not box chrome. | Swapped (`toolbar.tsx`). Added `rounded-none border-0 bg-transparent p-0` to cancel Designed's layered box chrome (Tailwind `utilities` layer wins over `ds.components` per the declared `@layer theme, base, ds, components, utilities` order). Verified: `toolbar.test.tsx` (role/name), full `vitest` suite, full Playwright suite, and a manual screenshot read of `e2e/screenshots/alerts.png` (toolbar renders as a bare flex row, no stray box). |
| Re-evaluation of upstream release (`designed-react@0.8.0`, `designed-icons@0.4.0` and `designed-tokens@0.6.0` unchanged) | Same dependency graph as 0.7.0 (`@base-ui/react@^1.9.0`, `@ktjn/designed-icons@^0.4.0`); `npm ls` still dedupes to a single `@base-ui/react@1.9.0` and single React 19. `Tabs.Tab` gained a `size?: "small" \| "medium"` prop; its `.small` CSS class sets `min-block-size: 1.75rem` (28px) and `font-size: 0.6875rem` (11px) — exactly Observable's dense-tab spec from feedback #6. `Toolbar` is unchanged (still no size prop, but that was never the actual blocker — see below). | Resolves feedback #6 for `Tabs` specifically. `Toolbar` row's half of #6 stays open (not actually blocking, see prior entry) since no size prop shipped for it. |
| Tabs (re-check) | Designed `Tabs` is a thin proxy over the exact same `@base-ui/react/tabs` Observable's own `tabs.tsx` already wrapped directly, with identical prop surface, now plus `size="small"` which sets the exact 28px/11px dense sizing Observable hand-rolled with `min-h-7`/`text-[11px]`. Base UI still emits `data-selected` (not Designed's dead `[data-active]` selector), so Observable's `data-[selected]:` Tailwind variants keep working unchanged. | Swapped (`tabs.tsx`). `TabsTab` now renders through `DesignedTabs.Tab` with `size="small"`; `TabsRoot`/`TabsList`/`TabsPanel` swapped to their Designed equivalents (same API, zero prop changes). Verified: `tabs.test.tsx` (3/3), full `vitest` suite, full Playwright suite, and a manual screenshot read of `e2e/screenshots/alerts.png` (Alert Rules/SLOs/Notification Channels tab bar renders identically — no padding leak). |
| Select | Designed `Select` is a compound Base UI listbox (`Select.Trigger`/`Select.Content`/`Select.Item`), not an `HTMLSelectElement`. Observable's `select.tsx` is a native `<select>` consumed by native `change` events and `<option>` children at every call site. | Not swapped — hard mismatch, same conclusion as the original evaluation. Native form semantics (autofill, mobile picker UI, `<form>` submission) would be lost for no stated requirement to replace them. |
| Copy button | Designed `CopyButton` (checked in installed `0.7.0`: `value`, `label`, `copiedLabel`, `copiedDuration`, `onCopy`, `onError`) still has no `size` prop and no hover-reveal visibility mode — Observable's `copy-button.tsx` needs `xs`/`sm` icon sizing in dense table rows and an `opacity-0 group-hover:opacity-100` reveal pattern, neither expressible through Designed's API. `useCopyToClipboard` also isn't exported for reuse outside the button. | Not swapped. Keep the hook and dense-row sizing/visibility behavior. Gaps: feedback #5 (still open upstream). |
| Metric card, description list, pill filter, data freshness | `Stat` (label/value/delta/trend/helpText) still lacks a tone border and sparkline slot. `DescriptionList` still has no copy/toggle row actions. `SegmentedControl` is still single-select with no per-item count or accent color. `RelativeTime` uses `Intl.RelativeTimeFormat` (`format: long\|short\|narrow`) and cannot reproduce Observable's exact compact `"12s ago"`/`"2m ago"`/`"2h ago"` strings that `data-freshness.test.tsx` asserts verbatim — adopting it would be a visible format change, not an internal refactor. | Keep Observable implementations. Gaps: feedback #7 (still open upstream, unaffected by this release). |
| Table | Designed `Table` adds sortable heads (`aria-sort`), sticky header, selected/expanded rows. No virtualization. | Keep `VirtualTable`. Candidate only for non-virtualized small tables (`table-panel`). |
| VirtualTable, time-series graph, topology, metric cells | Observable owns virtualization, telemetry semantics and drilldowns. | Retain the implementations. They can consume theme tokens independently. Retain Lucide coverage. |
| Panel, error-state, action-feedback, state vocabulary (`StateLabel`/`FreshnessNote`/`DataState`/`ConfidenceNotice`) | Designed's nearest generic equivalents (`Card`, `Alert`/`Banner`) don't carry Observable's domain semantics: `StateLabel`'s shape-coded icons (so state is legible without color), `ConfidenceNotice`/`DataState`'s specific ARIA roles and copy, `Panel`'s `eyebrow` slot. `Card` also renders a `<div>` root, not `<section>` — swapping `Panel` would drop its implicit landmark semantics for a purely cosmetic wrapper swap with no capability gained (same unlayered-CSS-override pattern as every other swap, zero new behavior). | Not evaluated as swap candidates — no generic Designed primitive carries the domain-specific accessibility contract these components exist for. Keep as Observable-owned. |
| [Styles and themes](../../apps/frontend/src/styles.css) | Tailwind v4 utilities coexist with Designed's layered CSS. | **Already done, in PR #1006 (before this doc's "Not attempted" note was written — corrected).** `:root[data-theme]` custom properties and the VT220 skin are gone; `styles.css` aliases Observable's existing `--bg`/`--text`/etc. names onto `--ds-color-*` tokens, driven solely by `data-color-scheme` (`src/lib/theme.tsx`). |
| Contrast and density tokens | `@ktjn/designed-tokens/css/all.css` (already imported once in `styles.css`) ships `[data-contrast="more"]` (WCAG high-contrast palette) and `[data-density="compact"]` (tighter `--ds-space-control-*`) token layers, neither activated anywhere — Observable's theme selector only exposed light/dark/system, no contrast option. | Wired up. `theme.tsx` gained `ContrastPreference` (`"default" \| "more"`, persisted to `localStorage` under `observable.contrast`, mirrors the existing theme-preference pattern) and sets `document.documentElement.dataset.density = "compact"` unconditionally (not a user preference — Observable's UI is dense everywhere). Added a "Contrast" `<select>` next to the existing Theme selector in `AppShell.tsx`. Verified: `tsc --noEmit`, `eslint`, full `vitest` (1017/1017), full Playwright (197/198, same pre-existing unrelated failure), and a live browser check (`data-density="compact"` produced no layout regression since Observable already sets its own spacing explicitly; toggling `data-contrast="more"` visibly strengthened borders/background contrast with no breakage). |

The [Designed manifests](https://github.com/ktjn/designed/tree/main/packages) declare React and tokens at 0.6.0 at review time. Its React package expects React/DOM 19, depends on icons transitively and pins Base UI 1.9.0. Observable's [lockfile](../../package-lock.json) resolves Base UI 1.6.0. These are source observations. Published tarball availability, package grants, bundle impact and rendered parity require consumer verification.

## Implementation sequence

1. **Prove distribution before committing a dependency.** From a clean checkout, resolve the published React and tokens versions through the scoped GitHub Packages registry. Inspect packed peer ranges and transitive icon resolution. Install exact versions in the frontend workspace, regenerate the root lockfile and check `npm ls react react-dom @base-ui/react`. Verify a single React instance and assess any duplicate Base UI size or interaction cost. Verify installs for local contributors, PR checks, Pages and the [frontend Docker build](../../apps/frontend/Dockerfile). Use read-only package access, a BuildKit secret for the install step and no credentials in image layers, client assets or untrusted PR jobs. If ordinary contributors or fork checks cannot install, resolve distribution upstream or defer adoption.
2. **Bridge styles and pilot two controls.** Record before screenshots and compressed production/playground JS and CSS sizes. Declare `@layer theme, base, ds, components, utilities` before the existing selective Tailwind imports. Import `@ktjn/designed-tokens/css/all.css` once. Remove Observable's `:root[data-theme]` palette blocks and the VT220 font-face/selection overrides from `styles.css`. Drive theming through `data-color-scheme` alone, switching between Designed's shipped schemes; update the theme selector's options and persisted preference to match. Implement Button and Input behind their current module paths, consuming Designed's palette directly with no Observable override layer. Remove redundant wrapper styling once the computed result matches the approved design.
3. **Accept or revert the pilot.** Run both Vite builds, focused wrapper tests, and the existing visual/navigation and accessibility suites in `apps/frontend`. Exercise a real consumer of each control in production and playground modes. Check form submission, type override, ref focus, disabled clicks, keyboard focus visibility and utility overrides. Review before/after screenshots in each Designed scheme the selector exposes, at dense table and toolbar widths. Verify CSS Modules survive production tree-shaking and the Pages base path. Record compressed bundle deltas and dependency-tree changes for review. Accept when behavior and accessibility checks pass and reviewers accept visual and size differences. Otherwise revert the pilot dependency, lockfile, CSS and wrapper changes together.
4. **Expand one component family per PR.** Prioritize badges and empty states, then evaluate overlays with real nested panels, theme inheritance, Escape and focus return. Record mismatches at the wrapper and leave the current implementation where a contract cannot be preserved. For an accepted technology decision, synchronize the frontend ADR and affected specifications before wider rollout. Upgrade exact package versions through reviewed lockfile changes and rerun the consumer checks.

Producer references: [installation, CSS layers and themes](https://github.com/ktjn/designed#installing-from-github-packages) and [public React API](https://github.com/ktjn/designed/blob/main/packages/react/api-report.d.ts).
