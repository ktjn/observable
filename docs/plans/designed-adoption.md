# Evaluate Designed in observable-web

**Decision accepted as [ADR-049](../../spec/adr/ADR-049-designed-component-library-adoption.md).** This file remains the live compatibility-findings record each new control family is evaluated against; the ADR records the accepted pattern.

Adopt shared controls incrementally if a consumer pilot passes. Observable's React 19 client, Vite CSS Modules support and npm workspace can consume Designed's compiled ESM. Designed's pnpm workspace is a producer detail. Routing, query state and telemetry rendering can keep their existing owners under [ADR-036](../../spec/adr/ADR-036-frontend-module-boundaries.md) and [ADR-016](../../spec/adr/ADR-016-grafana-visualization-strategy.md).

## Compatibility findings

| Observable surface | Designed fit | Decision |
| --- | --- | --- |
| [Button and Input](../../apps/frontend/src/components/ui/) | Native button and input semantics. Observable calls the destructive button variant `destructive`, Designed calls it `danger`. | Pilot through the existing exports. Preserve refs, default button type, form events, disabled behavior and consumer class overrides. |
| Badge, HealthDot and severity indicators | Designed Badge supports presentation. Observable Badge also supplies `role="status"` and HealthDot exposes a named state. | Keep severity mapping, labels and announcement behavior in Observable. No swap: Badge already renders through the Designed-token bridge (`styles.css`), so there is nothing left to integrate. |
| Empty state | Designed's `EmptyState` only accepts `icon`/`title`/`description`/`action` — no generic children slot and no per-slot `className`. Observable's `metadata` chip list and `compact` title-size override can't be expressed through it without reintroducing custom CSS the adoption is meant to remove. | Keep Observable's implementation. It already renders through the Designed-token bridge; no further integration possible without losing `metadata`/`compact`. |
| Select, confirm dialog, command palette | Observable Select exposes an actual `HTMLSelectElement`, option children and native change events. Designed Select is a compound control. Dialog and palette also own focus and portal behavior. | Keep native Select. Evaluate overlays individually after the pilot with keyboard, focus restoration and accessible-name tests. |
| Confirm dialog (overlay evaluation) | Designed's `AlertDialog` wraps Base UI: real focus trap, portal, and an `initialFocus`/`finalFocus` ref API, forwarded (though undeclared in its own prop types) through to the underlying Popup. Base UI disables pointer-outside dismissal for alertdialogs by design; Escape still fires `onOpenChange`, gated here by the existing `isPending` check since the component stays fully controlled by the `open` prop. `AlertDialogContent` (unlike `EmptyState`) accepts arbitrary children, so the consequences/elevated-context paragraphs needed no new slot. | Swapped. Preserves `role="alertdialog"`, accessible name/description wiring, Cancel-first focus (verified async via Base UI's post-paint floating-focus-manager, not the old synchronous effect), and explicit-confirmation requirement — existing `confirm-dialog.test.tsx` and the two consuming a11y tests (`obs_24_10`, `obs_25_10`) pass unchanged bar one `await waitFor` for the now-async initial focus. Fixed a pre-existing e2e failure (`experience-shell-s4`'s 320px-viewport confirm-resolve flow) as a side effect. Cost: Base UI's focus manager adds ~15.7 kB gzip to the main bundle — a real, overlay-specific price, unlike Button/Input. |
| Command palette (overlay evaluation) | Designed's `CommandPalette` owns `query` state internally with no `onQueryChange`/query-interception hook — `items` must be a static, homogeneous `{id, label, group, keywords, shortcut, disabled}` list filtered by its own internal `matchesQuery`. Observable's palette (`command-palette.tsx`) runs live async search across traces/services/incidents as the user types, with per-result-type (`nav`/`trace`/`service`/`incident`) custom rendering and navigation. There is no slot or callback to intercept the query string and substitute async, heterogeneously-rendered results. | Not swapped — hard mismatch, not a contract nuance to work around. Keep Observable's implementation. |
| Re-evaluation of upstream `main` (`ktjn/designed@619292f`, unreleased) | Registry still publishes only `designed-react` 0.6.0 / `designed-tokens` 0.6.0 / `designed-icons` 0.3.0; `main` carries pending changesets (`react-component-expansion`, `lucide-icon-expansion`). Source review only: no tarball was installed, no rendered parity or bundle size was measured. | All four upstream feedback items (#10-#13) are resolved in source. Re-run each affected evaluation row below against the released version before swapping anything. Do not bump the dependency to a git ref or tarball. |
| Empty state (re-check) | `EmptyState` now accepts `children` (rendered after `action`), `classNames: {icon,title,description,action}` and `titleAs`. | Unblocked in source. After release: swap, keep `metadata` as children and `compact` via `classNames.title`. |
| Command palette (re-check) | `CommandPalette` now has controlled `query`/`onQueryChange`, `filter={null}` to disable internal filtering, `renderItem`, generic `Item extends CommandPaletteItem` and `enableGlobalShortcut`. | Unblocked in source for async, heterogeneous results. Open items: group order and per-type navigation stay in Observable; verify listbox/combobox semantics, loading and error rows, and result-count announcements (no slot for a loading/error row, see feedback #8). |
| Confirm dialog (re-check) | `initialFocus`/`finalFocus` are now declared on `AlertDialog.Content` and `Dialog.Content`. | Remove the untyped spread in `confirm-dialog.tsx` after release. |
| Copy button | Designed `CopyButton` has `value`, `copiedLabel`, `copiedDuration`, `onCopy`, `onError`. No error visual state and no size scale. Observable's `useCopyToClipboard` hook is also used outside the button, and `xs`/`sm` icon sizes are used in dense rows. | Not swapped. Keep the hook. Gaps: feedback #5. |
| Tabs, toolbar | Designed `Tabs` and `Toolbar` wrap Base UI with the same part names Observable already uses. Neither exposes a density/size prop. Observable's tab is 11px / min-h 28px. | Candidate. Evaluate per family after release against the dense-toolbar and tab screenshots. Gap: feedback #6. |
| Metric card, description list, pill filter, data freshness | `Stat` (label/value/delta/trend/helpText) lacks tone border and sparkline slot. `DescriptionList` has no copy/toggle row actions. `SegmentedControl` is single-select with no per-item count or accent color. `RelativeTime` cannot show a stale/live status chip. | Keep Observable implementations. They can adopt Designed primitives internally (`RelativeTime` for the age text) once released. Gaps: feedback #7. |
| Table | Designed `Table` adds sortable heads (`aria-sort`), sticky header, selected/expanded rows. No virtualization. | Keep `VirtualTable`. Candidate only for non-virtualized small tables (`table-panel`). |
| VirtualTable, time-series graph, topology, metric cells | Observable owns virtualization, telemetry semantics and drilldowns. | Retain the implementations. They can consume theme tokens independently. Retain Lucide coverage. |
| [Styles and themes](../../apps/frontend/src/styles.css) | Tailwind v4 utilities coexist with Designed's layered CSS. Observable currently hand-maintains light, dark and VT220 palettes as `:root[data-theme]` custom properties and intentionally omits Preflight. | Retire Observable's palette custom properties and the VT220 skin (font, sizing and selection overrides). Adopt Designed's shipped themes (`data-color-scheme`) as the only source of truth; the theme selector exposes whatever schemes Designed publishes. Tailwind utilities keep handling layout and spacing, not palette color. |

The [Designed manifests](https://github.com/ktjn/designed/tree/main/packages) declare React and tokens at 0.6.0 at review time. Its React package expects React/DOM 19, depends on icons transitively and pins Base UI 1.9.0. Observable's [lockfile](../../package-lock.json) resolves Base UI 1.6.0. These are source observations. Published tarball availability, package grants, bundle impact and rendered parity require consumer verification.

## Implementation sequence

1. **Prove distribution before committing a dependency.** From a clean checkout, resolve the published React and tokens versions through the scoped GitHub Packages registry. Inspect packed peer ranges and transitive icon resolution. Install exact versions in the frontend workspace, regenerate the root lockfile and check `npm ls react react-dom @base-ui/react`. Verify a single React instance and assess any duplicate Base UI size or interaction cost. Verify installs for local contributors, PR checks, Pages and the [frontend Docker build](../../apps/frontend/Dockerfile). Use read-only package access, a BuildKit secret for the install step and no credentials in image layers, client assets or untrusted PR jobs. If ordinary contributors or fork checks cannot install, resolve distribution upstream or defer adoption.
2. **Bridge styles and pilot two controls.** Record before screenshots and compressed production/playground JS and CSS sizes. Declare `@layer theme, base, ds, components, utilities` before the existing selective Tailwind imports. Import `@ktjn/designed-tokens/css/all.css` once. Remove Observable's `:root[data-theme]` palette blocks and the VT220 font-face/selection overrides from `styles.css`. Drive theming through `data-color-scheme` alone, switching between Designed's shipped schemes; update the theme selector's options and persisted preference to match. Implement Button and Input behind their current module paths, consuming Designed's palette directly with no Observable override layer. Remove redundant wrapper styling once the computed result matches the approved design.
3. **Accept or revert the pilot.** Run both Vite builds, focused wrapper tests, and the existing visual/navigation and accessibility suites in `apps/frontend`. Exercise a real consumer of each control in production and playground modes. Check form submission, type override, ref focus, disabled clicks, keyboard focus visibility and utility overrides. Review before/after screenshots in each Designed scheme the selector exposes, at dense table and toolbar widths. Verify CSS Modules survive production tree-shaking and the Pages base path. Record compressed bundle deltas and dependency-tree changes for review. Accept when behavior and accessibility checks pass and reviewers accept visual and size differences. Otherwise revert the pilot dependency, lockfile, CSS and wrapper changes together.
4. **Expand one component family per PR.** Prioritize badges and empty states, then evaluate overlays with real nested panels, theme inheritance, Escape and focus return. Record mismatches at the wrapper and leave the current implementation where a contract cannot be preserved. For an accepted technology decision, synchronize the frontend ADR and affected specifications before wider rollout. Upgrade exact package versions through reviewed lockfile changes and rerun the consumer checks.

Producer references: [installation, CSS layers and themes](https://github.com/ktjn/designed#installing-from-github-packages) and [public React API](https://github.com/ktjn/designed/blob/main/packages/react/api-report.d.ts).
