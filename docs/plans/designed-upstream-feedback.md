# Upstream feedback for Designed

Issues and feature requests found while piloting `@ktjn/designed-react` in
observable-web ([designed-adoption.md](designed-adoption.md)). Upstream issues are linked below.

| # | Component | Issue | Suggested fix | Found in | Status (`designed@619292f`) |
| --- | --- | --- | --- | --- | --- |
| [1 (#10)](https://github.com/ktjn/designed/issues/10) | `AlertDialog.Content` (and likely `Dialog.Content`) | Base UI's `initialFocus`/`finalFocus` ref props work at runtime (forwarded via `...rest` to the underlying `Popup`) but aren't declared on `AlertDialogContentProps`. Consumers must cast through an untyped object spread to use them without a type error. | Add `initialFocus`/`finalFocus` to `AlertDialogContentProps` (and `DialogContentProps` if the same gap exists there), typed as Base UI's `DialogPopup` declares them. | `apps/frontend/src/components/ui/confirm-dialog.tsx` | Fixed in source, unreleased: declared on `AlertDialog.Content`/`Dialog.Content`. |
| [2 (#11)](https://github.com/ktjn/designed/issues/11) | `EmptyState` | No generic `children` slot and no per-slot `className` (`icon`/`title`/`description`/`action` each render fixed markup). A consumer that needs e.g. a metadata-chip list below the description, or a different title size for a "compact" variant, has no way to express it without abandoning the component. | Either accept a `children` slot after `action`, or accept `classNames: { title?, description?, action? }` for per-slot overrides. | Evaluated for `apps/frontend/src/components/ui/empty-state.tsx`; not adopted because of this gap (see [designed-adoption.md](designed-adoption.md) compatibility table) | Fixed in source, unreleased: `children`, `classNames`, `titleAs`. |
| [3 (#12)](https://github.com/ktjn/designed/issues/12) | `@ktjn/designed-react` → `@base-ui/react` | Pinned to an exact version (`"1.9.0"`, no `^`) in `dependencies`, not `peerDependencies`. Exact-pin a transitive dependency makes every designed-react bump a potential duplicate-install/version-skew risk for consumers who also depend on `@base-ui/react` directly (as this repo does, for its own Button/Input work prior to full migration). | Loosen to a caret range, or hoist `@base-ui/react` to a `peerDependency` since designed-react's public API re-exports Base UI types/behavior anyway. | `npm view @ktjn/designed-react@0.6.0 dependencies` during step 1 distribution check | Fixed in source: `"@base-ui/react": "^1.9.0"`. Still a `dependency`, not a peer; verify dedupe against Observable's lockfile on release. |
| [4 (#13)](https://github.com/ktjn/designed/issues/13) | `CommandPalette` | `query` is internal state with no `onQueryChange`/query-interception hook, and `items` must be a static, homogeneous list. A consumer that needs live/async search (hit an API per keystroke, mix result types with different rendering) has no way to plug in — the component can only filter a pre-supplied static list client-side. | Accept a controlled `query`/`onQueryChange` pair (uncontrolled fallback same as `open`), and/or a `renderItem` prop so item rendering isn't locked to `label`+`shortcut`. | Evaluated for `apps/frontend/src/components/ui/command-palette.tsx`; not adopted (see [designed-adoption.md](designed-adoption.md) compatibility table) | Fixed in source, unreleased: `query`/`onQueryChange`, `filter={null}`, `renderItem`. |
| 5 | `CopyButton` | No error visual state (only `onError` callback), no size scale (Observable needs `xs`/`sm` icon sizes in dense rows) and the copy logic is not exported as a hook. | Add `state` styling/`data-state="copied\|error"`, a `size` prop, and export `useCopyToClipboard`. | Source review for `apps/frontend/src/components/ui/copy-button.tsx` | Open, not filed |
| 6 | `Tabs`, `Toolbar` | No density/size prop; Observable's dense UI uses 11px text and 28px tab height. | Add `size: "small" \| "medium"` aligned with the standardized control sizes. | Source review for `tabs.tsx`, `toolbar.tsx` | Open, not filed |
| 7 | `Stat`, `DescriptionList`, `SegmentedControl`, `RelativeTime` | `Stat` has no tone accent or sparkline slot; `DescriptionList` items have no actions slot; `SegmentedControl` items have no count/accent; `RelativeTime` has no status adornment. | Slots or `classNames` per part, as already done for `EmptyState`. | Source review for `metric-card`, `dl-row`, `pill-filter`, `data-freshness` | Open, not filed |
| 8 | `CommandPalette` | No slot for loading/error/pending rows during async search, and no way to set result-count announcements. | `status`/`loading` prop or `footer` slot; `aria-live` message prop. | Source review for `command-palette.tsx` | Open, not filed |

## Notes
- Only one published version exists for `designed-react`/`designed-tokens`/`designed-icons` (`0.6.0`/`0.6.0`/`0.3.0`) at time of writing — not itself an issue, just means there's no migration-path precedent to learn from yet.
