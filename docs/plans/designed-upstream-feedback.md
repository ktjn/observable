# Upstream feedback for Designed

Issues and feature requests found while piloting `@ktjn/designed-react` in
observable-web ([designed-adoption.md](designed-adoption.md)). Upstream issues are linked below.

| # | Component | Issue | Suggested fix | Found in | Status (`designed-react@0.8.0`) |
| --- | --- | --- | --- | --- | --- |
| [1 (#10)](https://github.com/ktjn/designed/issues/10) | `AlertDialog.Content` (and likely `Dialog.Content`) | Base UI's `initialFocus`/`finalFocus` ref props work at runtime (forwarded via `...rest` to the underlying `Popup`) but aren't declared on `AlertDialogContentProps`. Consumers must cast through an untyped object spread to use them without a type error. | Add `initialFocus`/`finalFocus` to `AlertDialogContentProps` (and `DialogContentProps` if the same gap exists there), typed as Base UI's `DialogPopup` declares them. | `apps/frontend/src/components/ui/confirm-dialog.tsx` | **Released, verified.** `initialFocus`/`finalFocus` declared on `AlertDialogContentProps`. Removed the untyped spread in `confirm-dialog.tsx`; `tsc --noEmit` and `confirm-dialog.test.tsx` pass. |
| [2 (#11)](https://github.com/ktjn/designed/issues/11) | `EmptyState` | No generic `children` slot and no per-slot `className` (`icon`/`title`/`description`/`action` each render fixed markup). A consumer that needs e.g. a metadata-chip list below the description, or a different title size for a "compact" variant, has no way to express it without abandoning the component. | Either accept a `children` slot after `action`, or accept `classNames: { title?, description?, action? }` for per-slot overrides. | Evaluated for `apps/frontend/src/components/ui/empty-state.tsx`; not adopted because of this gap (see [designed-adoption.md](designed-adoption.md) compatibility table) | **Released, verified.** `children`, `classNames: {icon,title,description,action}`, `titleAs` all present in `EmptyStateProps`. Not yet swapped in Observable — tracked in [designed-adoption.md](designed-adoption.md). |
| [3 (#12)](https://github.com/ktjn/designed/issues/12) | `@ktjn/designed-react` → `@base-ui/react` | Pinned to an exact version (`"1.9.0"`, no `^`) in `dependencies`, not `peerDependencies`. Exact-pin a transitive dependency makes every designed-react bump a potential duplicate-install/version-skew risk for consumers who also depend on `@base-ui/react` directly (as this repo does, for its own Button/Input work prior to full migration). | Loosen to a caret range, or hoist `@base-ui/react` to a `peerDependency` since designed-react's public API re-exports Base UI types/behavior anyway. | `npm view @ktjn/designed-react@0.6.0 dependencies` during step 1 distribution check | **Partially released.** `"@base-ui/react": "^1.9.0"` — caret range fixed. Still a `dependency`, not a `peerDependency`. Verified: `npm ls @base-ui/react` dedupes to a single `1.9.0` instance against Observable's existing `^1.4.1` direct dependency; no duplicate install. Peer-dependency ask remains open. |
| [4 (#13)](https://github.com/ktjn/designed/issues/13) | `CommandPalette` | `query` is internal state with no `onQueryChange`/query-interception hook, and `items` must be a static, homogeneous list. A consumer that needs live/async search (hit an API per keystroke, mix result types with different rendering) has no way to plug in — the component can only filter a pre-supplied static list client-side. | Accept a controlled `query`/`onQueryChange` pair (uncontrolled fallback same as `open`), and/or a `renderItem` prop so item rendering isn't locked to `label`+`shortcut`. | Evaluated for `apps/frontend/src/components/ui/command-palette.tsx`; not adopted (see [designed-adoption.md](designed-adoption.md) compatibility table) | **Released, verified.** `query`/`onQueryChange`, `filter={null}`, `renderItem`, generic `Item extends CommandPaletteItem` all present. Not yet swapped in Observable — loading/error-row slot (#8) still open. |
| 5 | `CopyButton` | No error visual state (only `onError` callback), no size scale (Observable needs `xs`/`sm` icon sizes in dense rows) and the copy logic is not exported as a hook. | Add `state` styling/`data-state="copied\|error"`, a `size` prop, and export `useCopyToClipboard`. | Source review for `apps/frontend/src/components/ui/copy-button.tsx` | Open, not filed |
| 6 | `Tabs`, `Toolbar` | No density/size prop; Observable's dense UI uses 11px text and 28px tab height. | Add `size: "small" \| "medium"` aligned with the standardized control sizes. | Source review for `tabs.tsx`, `toolbar.tsx` | **`Tabs` resolved in 0.8.0, verified.** `TabsTab` gained `size?: "small" \| "medium"`; `.small` sets `min-block-size: 1.75rem` (28px) and `font-size: 0.6875rem` (11px) — exactly Observable's spec. Swapped `tabs.tsx` to `DesignedTabs.*` with `size="small"`; `tabs.test.tsx`, full `vitest`, full Playwright, and a screenshot of the alerts-page tab bar all confirm no regression. `Toolbar` was already swapped in 0.7.0 without needing this prop (its box-chrome was cancelable via `className`); no size prop shipped for it in 0.8.0, but nothing is blocked on it either. Closing this item. |
| 7 | `Stat`, `DescriptionList`, `SegmentedControl`, `RelativeTime` | `Stat` has no tone accent or sparkline slot; `DescriptionList` items have no actions slot; `SegmentedControl` items have no count/accent; `RelativeTime` has no status adornment. | Slots or `classNames` per part, as already done for `EmptyState`. | Source review for `metric-card`, `dl-row`, `pill-filter`, `data-freshness` | Open, not filed. Re-confirmed against installed `0.7.0`: unchanged. `RelativeTime` specifically also can't reproduce Observable's exact `"12s ago"`-style compact format (only `Intl.RelativeTimeFormat` `long`/`short`/`narrow`), which `data-freshness.test.tsx` asserts verbatim — a second, independent blocker beyond the missing status adornment. |
| 8 | `CommandPalette` | No slot for loading/error/pending rows during async search, and no way to set result-count announcements. | `status`/`loading` prop or `footer` slot; `aria-live` message prop. | Source review for `command-palette.tsx` | Open, not filed. `command-palette.tsx` was swapped to Designed's `CommandPalette` despite this gap — Observable's async fetch was already silent until resolved before the swap too, so this doesn't block adoption, only improves it. |
| 9 | `Input` | `InputProps` now narrows the native `size` attribute to `InputSize = "small" \| "medium" \| "large"` (via `Omit<InputHTMLAttributes<HTMLInputElement>, "size">`), introduced in 0.7.0. Any consumer wrapper that re-exports `InputHTMLAttributes<HTMLInputElement>` verbatim and spreads props through to `DesignedInput` now fails to typecheck, with no changeset/changelog entry calling out the breaking type change. | Call out breaking prop-type narrowing in the package changelog/changeset, since it isn't visible from a version bump alone (`0.6.0` → `0.7.0`, no major). | `apps/frontend/src/components/ui/input.tsx` (`tsc --noEmit` failure after bumping to `0.7.0`) | Found during this update; not filed. Worked around locally by narrowing Observable's own `InputProps` to `Omit<InputHTMLAttributes<HTMLInputElement>, "size">` (native `size` attribute unused by any caller). |
| 10 | `Select` | `Select` is a compound Base UI listbox (`Select.Trigger`/`Content`/`Item`) with no mode that renders a real `HTMLSelectElement`. Consumers that need native form semantics (mobile OS picker UI, autofill, native `<form>` submission without JS, native `change` events) have no way to get them — only the overlay. | Document that `Select` is overlay-only by design (so teams don't evaluate it expecting native semantics), or add a `native` rendering mode that renders `<select>`/`<option>` under the same component API for consumers that need it. | Evaluated for `apps/frontend/src/components/ui/select.tsx`; not adopted (see [designed-adoption.md](designed-adoption.md)) | Open, not filed. This is an architectural choice, not a bug — recording it so the team can decide whether it's worth an upstream ask or a permanent "keep native" decision. |
| 11 | `Card` | `CardRoot` always renders a `<div>` (no `as`/`role` prop for sectioning-element or landmark choice), and `CardHeader` has no generic slot before `Title` for a small-caps "eyebrow"/kicker label — the same per-slot gap `EmptyState` had before `classNames` was added. | Add `as` to `CardRoot` (mirrors `CardTitle`'s existing `as` prop), and either a `classNames`/`eyebrow` slot on `CardHeader`, or document `children` as composable so a consumer can place arbitrary content before `Title`. | Evaluated for `apps/frontend/src/components/ui/panel.tsx`; not adopted (see [designed-adoption.md](designed-adoption.md)) | Open, not filed. Low priority — `Panel`'s `<section>` landmark and `eyebrow` slot are easy to keep in Observable; filing this is only worth it if more consumers hit the same `as`/eyebrow gap. |
| 12 | `Alert`, `Banner`, `StatusIndicator` | All three differentiate state by color `variant` only. `Alert`/`Banner` accept an `icon` override so a consumer *can* inject a shape-coded icon per call site, but `StatusIndicator` — the closer match for an inline status badge — has no `icon` prop at all, only `children` (text). Observable's `StateLabel` requires shape-coded icons (circle/triangle/square/diamond/ring) in addition to text, not color alone, so state is legible without color (colorblind users, grayscale/forced-colors). | Add an `icon` slot to `StatusIndicator` matching `Alert`/`Banner`'s existing pattern. | Evaluated for `apps/frontend/src/components/ui/state.tsx` (`StateLabel`); not adopted (see [designed-adoption.md](designed-adoption.md)) | Open, not filed. Even with the slot, `Alert`/`Banner`/`StatusIndicator`'s `variant` enums (`info`/`success`/`warning`/`danger`/...) don't map 1:1 onto Observable's state vocabularies (`normal`/`degraded`/`unavailable`/`planned_maintenance`/`unknown`, or `empty`/`incomplete`/`delayed`/`stale`/`unavailable`/`restricted`) — the icon slot alone wouldn't be sufficient to adopt these components, just a prerequisite. |

## Notes
- Published versions as of this update: `designed-react@0.8.0`, `designed-tokens@0.6.0` (unchanged), `designed-icons@0.4.0` (unchanged).
